## 1 引言

### 1.1 编写目的

本文档系统阐述"基于大模型与规则引擎混合驱动的 IntelliJ IDEA 智能代码评审插件"（以下简称"本插件"）的功能需求、总体架构、模块详细设计、界面设计、使用与安装方法及测试验证情况，作为作品开发、验收与评审的依据。

### 1.2 项目背景

代码评审是保障软件质量的关键环节，但企业实践中普遍面临三个痛点：

1. **人工评审成本高、标准不一致**：评审质量依赖评审人经验，难以规模化。
2. **传统静态分析工具"看得见语法、看不懂框架"**：以规则匹配为主，误报率高，无法理解 Spring 等框架的语义约束（如事务代理机制），对"代码合法但运行期行为错误"的缺陷基本无感知。
3. **通用 AI 代码助手"只给建议、不给证据"**：结论缺乏可验证的推理依据，存在幻觉风险，且不主动做项目结构级分析。

本插件以"**确定性问题用确定性方法、语义问题用推理方法，两者互相校正**"为核心理念，面向企业 Java 开发场景重新设计与实现，将评审能力直接嵌入开发者日常使用的 IntelliJ IDEA 编辑器：以 PSI（程序结构接口）结构感知为基础，多源评审结果统一汇聚为带"证据链"的缺陷清单，并支持对局部问题一键修复，形成"评审—解释—修复"闭环。

### 1.3 术语与缩略语

| 术语 | 说明 |
|---|---|
| PSI | Program Structure Interface，IntelliJ 平台的程序结构接口，将源码解析为语法树供结构化分析 |
| PMD | 开源的 Java 静态代码分析工具，提供可编程 API 与内置规则集 |
| 证据链 | 每条评审意见附带的"问题位置 + 判定依据"说明，用于消除"黑盒结论" |
| 修复补丁 | 对可修复问题生成的替换文本，经 Diff 预览确认后写入源码文件 |
| 三路评审 | 框架感知分析、PMD 规则扫描、大模型语义评审三个独立评审来源 |

## 2 功能需求说明书

### 2.1 产品定位

本插件是一款运行于 IntelliJ IDEA 的**结构级精度代码评审工具**：对当前打开的 Java 文件执行多源评审，输出统一格式的缺陷清单（含来源、级别、行号、证据链），支持点击定位与一键修复。与通用代码助手的根本分界在于：**基于 PSI 的"结构级 + 框架语义"分析**，可检出传统文本规则工具无法覆盖的框架级缺陷。

### 2.2 用户角色与使用场景

| 角色 | 场景 |
|---|---|
| Java 开发者 | 提交代码前对当前文件自检，快速发现并修复问题 |
| 团队评审人 | 评审前对候选代码做预检查，聚焦高价值问题 |
| 教学/演示 | 展示"规则引擎 + 框架分析"混合评审与一键修复的完整链路 |

### 2.3 功能清单

| 编号 | 功能 | 说明 | 当前状态 |
|---|---|---|---|
| F1 | 评审入口 | 编辑器右键菜单触发，仅 Java 文件可见 | 已实现 |
| F2 | 框架感知分析 | 基于 PSI 检测 `@Transactional` 事务失效（缺 `rollbackFor`） | 已实现 |
| F3 | PMD 规则扫描 | 内嵌 PMD 引擎，启用未使用局部变量、空 catch 块两条规则 | 已实现 |
| F4 | 大模型语义评审 | 语义缺陷检测与规则误报复核的扩展通道 | 接口已预留，持续接入中 |
| F5 | 多源融合裁决 | 合并三路结果、去重、按严重度排序 | 已实现 |
| F6 | 评审结果面板 | 工具窗口表格展示：来源 / 级别 / 行号 / 问题描述 | 已实现 |
| F7 | 点击定位 | 双击结果行或点击按钮，跳转编辑器对应行 | 已实现 |

### 2.4 功能详述

#### 2.4.1 F1 评审入口

- 输入：用户在编辑器中打开一个 Java 文件并右键。
- 处理：菜单"智能代码评审"仅在当前文件为 Java 文件（`PsiJavaFile`）时可见可点击；触发后调用融合评审服务并打开结果面板。
- 输出：结果面板自动弹出并展示本次评审的全部缺陷。

#### 2.4.2 F2 框架感知分析（核心功能）

- 规则编号：`TransactionRollbackFor`。
- 检测逻辑：遍历文件内所有方法，识别标注了 Spring `@Transactional` 的方法；若方法声明 `throws` 受检异常（非 `RuntimeException` / `Error` 家族），且注解未配置 `rollbackFor` 或 `rollbackForClassName`，则判定该事务方法存在"异常不回滚"风险。
- 判定依据：Spring 声明式事务默认仅对 `RuntimeException` 与 `Error` 回滚；受检异常抛出后事务将提交，造成数据不一致。
- 输出：严重级别为"严重"（CRITICAL）的缺陷项，证据链包含方法名、涉及异常类型及判定依据。
- 可修复：是（在注解中补充 `rollbackFor = Exception.class`）。

#### 2.4.3 F3 PMD 规则扫描

- 启用规则：`UnusedLocalVariable`（未使用局部变量，最佳实践类）、`EmptyCatchBlock`（空 catch 块，易错类）。
- 处理：将文件文本提交内嵌 PMD 引擎扫描，规则违规转换为统一缺陷模型；严重级别按 PMD 优先级映射（P1~P2 → 严重，P3 → 警告，P4 → 建议，P5 → 提示）。
- 容错：扫描依赖初始化失败或解析异常时降级为空结果并记录警告日志，不影响其他评审来源。
- 可修复：两条规则均支持（删除未使用变量行；空 catch 块内补充异常处理语句）。

#### 2.4.4 F4 大模型语义评审（扩展通道）

- 定位：补足规则族无法覆盖的语义/上下文类缺陷（如跨方法调用的事务失效、命名与语义不一致等），并承担对规则命中项的误报复核。
- 当前状态：评审服务中已预留独立通道（`ReviewService.runLlmReview`），统一缺陷模型已内置 `Source.LLM` 来源标识，JSON 解析依赖（Jackson）已就绪；接入方案见 4.5 节，正在持续接入。

#### 2.4.5 F5 多源融合裁决

- 去重：以"文件路径 + 起始行 + 问题描述"为唯一键去重，多个来源对同一位置同类问题的重复命中只保留一条。
- 排序：按严重级别降序（严重 → 警告 → 建议 → 提示）输出，高优问题排在面板顶部。

#### 2.4.6 F6/F7 结果展示与定位

- 面板列：来源（规则引擎 / 大模型）、级别（严重 / 警告 / 建议 / 提示）、行号、问题描述（自动换行、行高自适应）。
- 定位：双击结果行或选中后点击"跳转到代码"，编辑器打开对应文件并跳转至问题行；行号越界时自动钳制到有效范围，不中断操作。

#### 2.4.7 F8 一键修复

- 适用范围：事务缺 `rollbackFor`（补充注解属性）、未使用局部变量（删除整行）、空 catch 块（补充"包装抛出"语句）。
- 流程：生成修复补丁 → 弹出 Diff 预览（左"当前代码"、右"修复后"）→ 用户确认 → 写入文件并跳转至修改位置。
- 安全策略：全部修改在平台"写命令"中执行（支持 Ctrl+Z 撤销）；找不到文件、无补丁、补丁结构不符等情形均有友好提示，不做盲目替换。

### 2.5 非功能需求

| 类别 | 要求 | 实现情况 |
|---|---|---|
| 性能 | 单文件评审秒级返回 | 三路均为单文件级分析，PMD 秒级完成 |
| 兼容性 | 支持 IDEA 2024.2 及以上版本 | `sinceBuild = 242`，按 2024.2 平台编译 |

### 3.3 核心数据契约 IssueModel

`IssueModel` 是三个模块之间**唯一**的通信契约，任何评审来源产出、面板展示、修复执行均围绕该模型进行。

| 字段 | 类型 | 说明 |
|---|---|---|
| id | String | 缺陷唯一标识（UUID） |
| source | Source 枚举 | 来源：`RULE`（规则引擎）/ `LLM`（大模型） |
| ruleId | String | 规则编号（如 `TransactionRollbackFor`、`UnusedLocalVariable`） |
| severity | Severity 枚举 | 级别：CRITICAL / MAJOR / MINOR / INFO（声明顺序即严重度降序） |
| filePath | String | 目标文件全局路径 |
| startLine / endLine | int | 问题行号区间（1 起，含两端） |
| message | String | 一句话问题描述（面板展示） |
| evidence | String | 证据链：判定依据（如"方法 X 声明 throws IOException；注解未配置 rollbackFor，Spring 默认仅对 RuntimeException 与 Error 回滚"） |
| fixable | boolean | 是否支持一键修复 |
| fixPatch | String | 修复补丁：替换 `[startLine, endLine]` 区间内容的修复后文本；**空串表示删除整行** |

### 3.6 关键设计决策

| 决策 | 内容 | 理由 |
|---|---|---|
| D1 确定性优先 | 规则类问题（事务、PMD）由确定性引擎产出，不依赖网络与大模型 | 结果可复现、零幻觉、毫秒级；保障演示与生产可靠性 |

| D6 契约先行 | 三模块仅通过 `IssueModel` 与两个接口签名通信 | 三人并行开发互不阻塞，可独立测试 |

## 4 详细设计说明书

### 4.1 评审入口模块（ReviewAction）

- 注册：`plugin.xml` 中将 Action 挂载到 `EditorPopupMenu` 组（锚点 first），菜单文本"智能代码评审"。
- 可见性控制：`update()` 中仅当上下文文件为 `JavaPsiFile` 时启用并可见，非 Java 文件不出现菜单项；按新平台规范声明更新线程为 `ActionUpdateThread.BGT`。
- 执行流程：
  1. 获取当前项目与 PSI 文件，任一为空直接返回；
  2. 构造融合评审服务 `ReviewService(new TransactionalAnalyzer())` 并同步调用 `review(file)`；
  3. 获取"代码评审"工具窗口（ID 与 `plugin.xml` 保持一致），未注册则弹错误提示；
  4. `toolWindow.show()` 后通过 `invokeLater` 延迟到事件队列末尾填充数据——工具窗口首次打开时内容异步创建，直接取索引会越界；
  5. 填充时遍历窗口内所有 `Content`，按类型匹配 `ReviewPanel` 再注入数据（不按索引取值，规避越界风险）；
  6. 记录日志：`触发评审: 文件名，结果 N 条`。

### 4.2 融合评审服务（ReviewService）

对外唯一入口 `review(PsiFile): List<IssueModel>`，内部流水线如下：

1. **框架分析**：调用 `frameworkAnalyzer.analyze(psiFile)`，获取框架级缺陷；
2. **PMD 扫描**：`runPmdScan(filePath, fileText)`，将规则违规转为统一模型；
3. **大模型通道**：`runLlmReview(...)`，当前为预留实现（返回空列表），接口与数据结构已就绪；
4. **日志留痕**：记录 `引擎结果：框架 X 条，PMD Y 条，LLM Z 条`，便于真机排查；
5. **去重**：以 `文件路径|起始行|问题描述` 为键，重复命中保留先插入者；
6. **排序**：按 `Severity` 枚举声明顺序（严重 → 提示）升序排列，即严重度降序展示；
7. **补丁生成**：对 `fixable` 的缺陷逐条调用 `generatePatch(issue, fileText)` 填充 `fixPatch`；
8. 返回最终列表。

**补丁生成规则**（`generatePatch`）：

| 规则 | 补丁策略 | 安全校验 |
|---|---|---|
| `TransactionRollbackFor` | 在 `@Transactional` 注解内插入 `rollbackFor = Exception.class`（已有属性时前插、无属性时补括号） | 行内圆括号不配平（跨行注解）则不生成，避免误伤 |
| `UnusedLocalVariable` | 空补丁（应用层按约定删除整行） | 行号越界不生成 |
| `EmptyCatchBlock` | 保留 catch 头与块尾括号，块内补充 `throw new IllegalStateException("捕获到未处理异常", 原异常变量)` | catch 结构不符（块内已有其他行、尾行非 `}`）则不生成 |

### 4.3 PMD 规则引擎集成（关键实现点）

- 集成方式：以 Java API 方式内嵌 PMD 7.4.0（`PmdAnalysis`），不安装任何外部工具；分析输入为编辑器内存文本（含未保存修改），不要求文件落盘。
- 规则集：`category/java/bestpractices.xml/UnusedLocalVariable`、`category/java/errorprone.xml/EmptyCatchBlock`（单文件级规则，保证秒级返回与演示可控）。
- **关键修复（类加载器）**：IDEA 插件类加载器对 JDK 资源（`java/lang/*.class`）不可见，PMD 类型系统初始化会因取不到基础类资源而失败。实现中显式将 PMD 配置类加载器指定为平台类加载器（`ClassLoader.getPlatformClassLoader()`），并使 PMD 的类加载器随后续版本迭代保持可解析 JDK 基础类资源的性质（已由回归测试锁定）。
- 结果转换：违规项映射为 `IssueModel`（来源 `RULE`），PMD 优先级映射到四级严重度；命中可修复清单的规则标记 `fixable`。

### 4.4 框架感知分析器（TransactionalAnalyzer）

**接口**：`FrameworkAnalyzer.analyze(PsiFile): List<IssueModel>`，面向扩展设计的规则容器，可容纳后续多条框架级规则。

**实现要点**：

1. **读动作自包含**：`analyze` 内部以 `ReadAction.compute` 包裹全部分析过程，保证从任意线程调用均满足新版平台线程断言。
2. **方法遍历**：以 `JavaRecursiveElementVisitor` 遍历文件内全部方法（含嵌套类中的方法）。
3. **注解识别（双通道）**：
   - 优先通道：解析注解引用，解析结果的全限定名为 `org.springframework.transaction.annotation.Transactional` 时命中；
   - 降级通道：演示/评审工程未引入 Spring 依赖、注解无法解析（`resolve()` 返回空）时，按注解短名 `Transactional` 匹配；
   - 注意点：注解无法解析时 `getQualifiedName()` 返回短名而非空值，不能以其为空判断"未解析"，必须以引用元素的 `resolve()` 结果为准。
4. **回滚配置判定**：注解存在 `rollbackFor` 或 `rollbackForClassName` 属性即视为已配置，跳过。
5. **受检异常识别**：
   - 标准路径：对 `throws` 列表逐个解析类型，保留"是 `Throwable` 子类且非 `RuntimeException` / `Error` 家族"的异常；
   - **降级路径**：类型无法解析（工程未关联 JDK、索引未就绪）时按短名启发式处理——命中 `*RuntimeException`、`*Error` 及常见非受检异常名单（`IllegalArgumentException`、`NullPointerException` 等）则跳过；其余按受检异常兜底认定并记录诊断日志（`事务分析：异常类型 X 未能解析，按受检异常兜底处理`），保证解析环境不完整时仍能检出（宁可提示、不可漏报）。
6. **缺陷构造**：定位到注解所在行，级别固定"严重"，证据链写明"方法名 + throws 的异常清单 + Spring 默认回滚规则"，标记可修复。

### 4.5 大模型语义评审通道（预留设计）

- 通道位置：`ReviewService.runLlmReview(sourceCode, filePath)`，当前返回空列表，不影响既有链路运行。
- 已就绪基础：统一模型的 `Source.LLM` 来源枚举；Jackson 依赖；面板来源列显示"大模型"。
- 接入设计（正在持续接入）：
  1. **输入构造**：源码 + 文件路径 + 规则引擎已命中的问题清单（作为上下文约束注入，抑制幻觉）；
  2. **评审 Prompt**：要求模型对"规则覆盖不到的语义问题"给出结构化 JSON 输出（问题类别、行号、描述、依据）；
  3. **解析落库**：JSON 反序列化为 `IssueModel`（来源 `LLM`），与规则结果同流去重、排序、展示；
  4. **误报复核**：对规则命中项由模型二次判定"是否误报"，复核结论并入证据链展示；
  5. **兜底**：超时/断网时降级为"仅规则引擎"模式，评审链路不中断。

### 4.6 结果面板模块（ReviewPanel / ReviewToolWindowFactory）

- 工具窗口：注册于右侧（`anchor = right`），ID"代码评审"，由 `ReviewToolWindowFactory` 创建 `ReviewPanel`。
- 表格设计：
  - 四列：来源 / 级别 / 行号 / 问题描述；采用"最后一列吃余宽"的自适应模式，描述列固定较宽；
  - 描述列以 `JTextArea` 渲染器实现自动换行；
  - **行高自适应**：逐行按"当前列宽"预置渲染组件尺寸后计算换行高度（仅设尺寸才能得到真实折行高度），首次填充后延迟一帧按最终列宽二次校正——解决"首次打开行高偏窄、文字显示不全"问题；
  - 来源与级别以中文展示（规则引擎/大模型；严重/警告/建议/提示），面向演示更直观。
- 交互：双击数据行跳转（规避单击误触）；底部按钮区"跳转到代码"与"应用修复"作用于当前选中行；未选中时给出提示。
- 定位实现：按 `filePath` 定位虚拟文件 → 读动作内取文档行数并将目标行钳制到 `[1, 行数]` → `OpenFileDescriptor`（0 基行号）导航并高亮；文件缺失仅记录日志，不弹窗打扰。

### 4.7 一键修复模块（FixApplier）

- 入口：`previewAndApply(Project, IssueModel)`。
- 前置校验：不可修复/无补丁 → 提示"该问题暂无可用修复"；文件不存在/不可读 → 相应警告。
- 区间计算（读动作内完成）：
  - 行号钳制到文档有效范围；
  - 替换区间 = `[起始行首偏移, 结束行尾偏移]`；
  - **空补丁（删行）语义**：区间扩展到行尾换行符——非末行时替换终点延伸至下一行行首；末行时替换起点回退至上一行行尾，保证删除后不残留空行。
- Diff 预览：截取当前区间文本作为左侧"当前代码"，`fixPatch` 作为右侧"修复后"，以模态 Diff 对话框展示（左右内容均使用 `DiffContentFactory.create(String)` 构造）。
- 应用：用户在确认对话框选择"是"后，于 `WriteCommandAction` 中执行区间文本替换（平台规范，支持 Ctrl+Z 撤销），并导航至修改位置。

### 4.8 线程模型与平台兼容性设计

新版 IDEA 平台（2025.x / 2026.x）对线程断言显著收紧，本插件按"面向未来版本"的标准实现：

| 场景 | 规范做法 | 涉及位置 |
|---|---|---|
| 读取文档模型（行数、文本、偏移） | `ReadAction.compute` 包装，EDT 场景同样适用 | 事务分析、跳转、修复 |
| 修改文档 | `WriteCommandAction.runWriteCommandAction` | 修复应用 |
| 工具窗口异步内容 | `ApplicationManager.invokeLater` 延迟填充 | 评审入口 |
| Action 更新线程 | 显式声明 `ActionUpdateThread.BGT` | 评审入口 |
| 事件回调中的 UI 调整 | `SwingUtilities.invokeLater` 二次校正 | 面板行高 |

### 4.9 关键流程时序

**评审流程**：

```
用户右键 → ReviewAction
  ├─ 取 Project / PsiFile，构造 ReviewService
  ├─ TransactionalAnalyzer.analyze（PSI 结构分析，含受检异常判定）
  ├─ runPmdScan（内嵌 PMD 单文件扫描）
  ├─ runLlmReview（预留通道）
  ├─ 去重 → 按严重度排序 → 生成修复补丁
  ├─ toolWindow.show() + invokeLater 填充 ReviewPanel
  └─ 日志：引擎结果统计
```

**修复流程**：

```
选中问题 → 点击"应用修复" → FixApplier.previewAndApply
  ├─ 校验 fixable / 补丁 / 文件存在性
  ├─ 读动作内：行号钳制 + 替换区间计算（含删行扩展）
  ├─ Diff 预览（当前代码 ↔ 修复后）→ 模态确认
  └─ WriteCommandAction 替换文本 → 导航至修改位置
```

## 5 数据库设计说明

本项目为 IDE 端本地工具，**不涉及数据库设计**，特此说明：

1. **无持久化存储**：评审数据（`IssueModel`）全程在内存中流转，单次评审完成后即释放，不落盘、不建库。
2. **无用户数据采集**：插件不收集、不上传任何代码或用户信息，全部分析在本地完成。
3. **源码即数据源**：分析输入为编辑器内存中的最新文本（含未保存修改）；修复动作直接写回源码文件，通过编辑器原生撤销（Ctrl+Z）即可回滚，与 IDE 的文档管理机制天然一致。
4. **扩展说明**：如后续需要评审历史记录等能力，可基于 IntelliJ 平台内置的持久化机制（`PersistentStateComponent`）扩展，无需引入外部数据库。

## 6 软件界面设计书

### 6.1 界面总览

本插件共包含三个界面单元：

| 单元 | 形式 | 功能 |
|---|---|---|
| 评审入口 | 编辑器右键菜单项 | 触发对当前 Java 文件的评审 |
| 评审结果面板 | 右侧工具窗口（ToolWindow） | 展示缺陷清单，支持定位与修复 |
| 修复预览对话框 | 模态 Diff 窗口 | 对比"当前代码"与"修复后"，供用户确认 |

界面设计原则：**轻量嵌入、不打断心流**。插件不新增独立窗口、不改变 IDE 既有布局习惯；结果面板与 IDEA 原生工具窗口风格一致（右侧停靠，可折叠、可固定）。

### 6.2 评审入口菜单

- 位置：编辑器代码区右键菜单**首项**（`EditorPopupMenu`，锚点 first），名称为"**智能代码评审**"。
- 可见性：仅在当前文件为 Java 文件时显示；其他类型文件不出现该菜单，避免误操作。
- 行为：点击后立即执行评审并自动弹出（显示）结果面板。

### 6.3 评审结果面板

- 位置：IDE 右侧工具窗口，标题栏为"**代码评审**"。
- 布局：上部为结果表格（随窗口宽度自适应），下部为操作按钮区（"跳转到代码"、"应用修复"）。
- 表格列设计：

| 列 | 宽度策略 | 内容 | 说明 |
|---|---|---|---|
| 来源 | 固定（约 70px） | 规则引擎 / 大模型 | 标识缺陷的检测来源 |
| 级别 | 固定（约 80px） | 严重 / 警告 / 建议 / 提示 | 对应 CRITICAL / MAJOR / MINOR / INFO |
| 行号 | 固定（约 50px） | 数字（1 起） | 缺陷所在起始行 |
| 问题描述 | 占满剩余宽度 | 一句话问题描述 | 自动换行，行高随内容自适应 |

- 视觉细节：问题描述列采用自动换行渲染，面板对每一行按内容计算行高，保证长描述完整可见；首屏加载后按最终列宽二次校正，避免展示不全。
- 行为设计：
  - **双击**数据行 → 跳转至对应代码行（规避单击误触）；
  - 选中行后点击"跳转到代码"→ 等效定位；
  - 选中行后点击"应用修复"→ 进入修复预览流程；
  - 未选中任何行直接点击按钮 → 弹出提示"请先在列表里选中一条问题"。

### 6.4 修复预览与提示

- 修复预览：模态 Diff 窗口，标题为"修复预览 - {问题描述}"；左侧"当前代码"、右侧"修复后"；关闭预览后弹出确认框"**是否应用该修复？**"，选择"是"执行写入并跳转到修改位置，选择"否"放弃。
- 提示文案规范（统一标题"智能代码评审"）：

| 场景 | 类型 | 文案 |
|---|---|---|
| 问题不可修复 | 信息 | 该问题暂无可用修复 |
| 目标文件丢失 | 警告 | 找不到目标文件 |
| 文件内容不可读 | 警告 | 无法读取文件内容 |
| 未选中行 | 信息 | 请先在列表里选中一条问题 |
| 工具窗口缺失（异常） | 错误 | 未找到评审结果窗口 |

### 6.5 交互设计原则

1. **可撤销**：所有代码修改均通过平台写命令执行，天然支持 Ctrl+Z；
2. **先预览后应用**：任何修复必须先经 Diff 预览与显式确认，杜绝静默改码；
3. **失败不打扰**：定位失败、文件缺失等非关键异常仅记录日志或轻提示，不用弹窗打断工作流；
4. **防误触**：跳转采用双击手势；行号越界自动钳制，避免异常。

## 7 用户操作手册

### 7.1 前置条件

- IntelliJ IDEA 2024.2 及以上版本（社区版/终极版均可）；
- 已按第 8 章完成插件安装并重启 IDE；
- 待评审文件为 Java 源码文件。

### 7.2 标准操作流程

1. **打开文件**：在 IDEA 中打开待评审的 Java 文件（无需保存，编辑器中的最新内容即评审对象）。
2. **触发评审**：在代码编辑区右键 → 选择"**智能代码评审**"；右侧"代码评审"面板自动弹出并展示结果。
3. **查看结果**：面板表格逐条列出问题（来源/级别/行号/描述），严重度高的问题排在前面。
4. **定位问题**：双击某一行（或选中后点"跳转到代码"），编辑器即跳转并高亮到对应代码行。
5. **一键修复**：选中一条可修复问题 → 点击"应用修复" → 在 Diff 预览中核对修改 → 确认框选择"是" → 修改即写入文件，光标自动跳转到修改处。
6. **撤销修改**：如需回退，在编辑器中按 Ctrl+Z 即可（与普通编辑一致）。

### 7.3 典型评审场景（演示样本）

仓库 `demo/` 目录内置两个演示样本，用于验证评审链路与展示效果：

| 样本 | 文件 | 预期结果 |
|---|---|---|
| 样本一：订单服务 | `demo/DemoOrderService.java` | 3 条：事务失效 1 条（严重）+ 未使用变量 1 条 + 空 catch 块 1 条 |
| 样本二：用户服务 | `demo/DemoUserService.java` | 4 条：事务失效 1 条（严重）+ 未使用变量 2 条 + 空 catch 块 1 条 |

样本二另含 2 处**合规写法**（已正确配置 `rollbackFor`、事务方法只抛运行时异常），评审正确时**不应**对其报告问题，用于验证"不误报"。

**实时分析验证（现场演示动作）**：评审读取的是编辑器实时内容——现场删掉样本二事务注解中的 `rollbackFor = Exception.class`（第 28 行），重新评审后问题数由 4 条变为 5 条；Ctrl+Z 还原后恢复为 4 条，可证明评审结果并非预置数据。

### 7.4 常见问题（FAQ）

| 问题 | 排查 |
|---|---|
| 右键菜单里没有"智能代码评审" | 确认当前文件是 Java 文件；确认插件已启用（Settings → Plugins） |
| 评审后面板为空/条数偏少 | 查看 IDEA 日志（Help → Show Log）中"引擎结果"行，确认各来源命中数 |
| 点击"应用修复"提示"该问题暂无可用修复" | 该问题属于"提示类"（无补丁的方案性问题），当前仅三类问题支持修复 |
| 跳转行号与实际不符 | 文件可能在评审后被外部修改，重新评审后再定位即可（插件已对越界行号做保护） |
| 修改文件后想回退 | 编辑器内 Ctrl+Z，或使用本地版本管理回滚 |
